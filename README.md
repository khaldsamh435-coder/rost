# School Portal — المنصة المدرسية

نسخة أولية قابلة للتشغيل والتطوير باستخدام HTML/CSS/JavaScript وSupabase.

## محتويات المشروع
- `index.html` الواجهات الأساسية وتسجيل الدخول والتسجيل.
- `styles.css` التصميم المتجاوب ودعم RTL.
- `app.js` منطق التطبيق وربط Supabase.
- `config.example.js` نموذج إعداد الاتصال.
- `supabase-schema.sql` الجداول والعلاقات وسياسات RLS وStorage.

## التشغيل
1. أنشئ مشروعًا جديدًا في [Supabase](https://supabase.com/).
2. افتح SQL Editor ونفّذ كامل ملف `supabase-schema.sql`.
3. من Project Settings ثم API انسخ Project URL و anon/publishable key.
4. انسخ `config.example.js` وسمّ النسخة `config.js`، ثم ضع القيم الصحيحة.
5. افتح `index.html` عبر خادم محلي أو انشر المجلد على Vercel. لا تعتمد على فتح الملف مباشرة إذا منع المتصفح بعض الموارد.
6. في Supabase Authentication راجع إعدادات تأكيد البريد الإلكتروني وروابط إعادة التوجيه لموقعك.

## إنشاء مدير واعتماد المدرسين
- أنشئ حسابًا عاديًا من التطبيق ببريد المدير.
- بعد تأكيد البريد، نفّذ استعلام ترقية المدير الموجود في نهاية `supabase-schema.sql` بعد تعديل البريد.
- حسابات التسجيل العامة تُنشأ كطلاب فقط.
- اعتماد المدرس يجب أن يتم يدويًا من مسؤول موثوق بعد التحقق من هويته. يمكن ترقية الحساب عبر استعلام SQL المرفق.

## الأمان — اقرأ قبل الاستخدام الفعلي
- لا تضع `service_role` أو أي مفتاح سري في `config.js` أو ملفات الواجهة.
- الكود التعريفي يُولّد داخل قاعدة البيانات ويُعرض عبر RPC للمستخدم المصادق عليه فقط. لا يُستخدم الكود وحده لتسجيل الدخول أو استعادة الحساب.
- RLS مفعّل على الجداول الأساسية؛ اختبر السياسات بحساب طالب من كل صف، ومدرس غير معتمد، ومدرس معتمد، ومدير.
- واجهة الإدارة الحالية تعرض قائمة الحسابات وتتيح اعتماد المدرسين، لكنها ليست بديلًا عن إجراءات إدارة مؤسسية أو سجل تدقيق كامل.
- يجب تفعيل SMTP موثوق، وضبط Redirect URLs، وسياسات كلمات المرور ومعدل المحاولات في Supabase.
- يجب استكمال تدفق استعادة كلمة المرور والتحقق الإضافي قبل تعديل البيانات الحساسة قبل إطلاق عام.
- رفع الملفات في هذه النسخة متاح للمدرسين المعتمدين فقط. آلية تسليم ملفات الطلاب تحتاج سياسة رفع منفصلة قبل تفعيلها.
- يجب مراجعة سياسات Storage واختبارها عمليًا؛ تنزيل الملف يتم عبر رابط مؤقت قصير الصلاحية.
- لا توجد بعد إشعارات فورية أو تسليم إلكتروني من الواجهة؛ الجداول والسياسات الأساسية موجودة لتوسعتها في المرحلة التالية.
- لا تستخدم بيانات طلاب حقيقية قبل مراجعة أمنية واختبار صلاحيات مستقل وموافقة المدرسة وأولياء الأمور حيث يلزم.

## بنية البيانات
- `profiles`: ملف المستخدم ودوره وصفه والكود الخاص.
- `content_items`: الأخبار والحصص والواجبات والتقييمات.
- `submissions`: تسليمات الطلاب.
- `notifications`: إشعارات المستخدمين.
- `admin_audit_log`: أساس لسجل العمليات الإدارية.
- `storage.objects`: الملفات الخاصة.

## النشر على Vercel
ارفع الملفات إلى GitHub ثم استورد المستودع في Vercel. تأكد من وجود `config.js` في جذر النشر. لا ترفع مفاتيح سرية؛ مفتاح anon/publishable مخصص للواجهة ويجب أن تكون الحماية عبر RLS.
